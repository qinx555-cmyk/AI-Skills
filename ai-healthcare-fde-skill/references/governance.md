# 风险、验证与生产治理

## Human-in-the-loop 验证记录

每个验证样例至少记录：

| 字段 | 内容 |
|---|---|
| 输入样例 | 真实业务输入，或经批准的脱敏/合成测试样例 |
| AI 原始输出 | 完整保留，不用人工修订后的版本覆盖 |
| 专家结论 | 领域专家给出的正确结果或可接受范围 |
| 一致性 | 正确 / 部分正确 / 错误 |
| 错误类型 | 幻觉、遗漏、逻辑、引用、边界越权、格式或流程错误 |
| 严重度 | 低 / 中 / 高 / 禁止上线 |
| 修正措施 | Prompt、规则、知识库、模型、数据或人工门控 |

任何修正都应通过回归集验证，避免修好单个案例却破坏其他路径。

## Golden Dataset

至少包含：高频正常案例、真实典型异常、边界/信息不足/术语歧义案例、红线越权案例和版本回归案例。记录来源、授权、脱敏状态、标签责任人、适用范围、版本和变更原因。

Golden Dataset 不是一次性准确率测试集；它是版本 Gate。数据分布明显变化、业务规则改变或模型/知识库升级时，应评估是否需要扩充或重新标注。

## 生产化最低能力

| 能力域 | 必须具备 |
|---|---|
| 身份与权限 | SSO/账号、最小权限、角色隔离、敏感功能审批 |
| 数据 | 来源登记、授权、脱敏/加密、边界和保留策略 |
| 模型与知识 | 模型、Prompt、知识库和规则的版本与引用来源 |
| 监控 | 使用量、质量指标、严重错误、延迟、成本和漂移信号 |
| 审计 | 谁在何时使用什么输入/数据，模型输出什么，谁审核，最终是否采用 |
| 兜底 | 人工接管、回滚、停用、异常告警和事件处置 |
| 培训 | 使用说明、责任边界、禁止事项和升级路径 |

## 上线验收

- 技术：准确率/召回率等任务指标、幻觉或不可证实率、响应时间、系统可用性。
- 业务：节省工时、任务完成率、周期缩短、返工和质量指标变化。
- 用户：活跃率、采纳率、人工修改率、满意度与工作负担。
- 风险：严重错误、越权、未授权访问、人工接管、审计异常和回滚演练。

指标需关联 Baseline、样本量、测试范围和责任人。平均指标不能掩盖红线案例失败。

## 强制人工升级

出现任一情况立即交由授权人员：

- 涉及最终诊断或治疗决定；
- 涉及质量放行、CAPA 关闭或正式注册提交；
- AI 无法给出依据，或来源彼此冲突；
- 输入质量异常、权限不明或信息不足；
- 输出与企业规则、法规或专业判断冲突；
- 重复严重错误，或超出已验证边界。

## 数据隔离

| 层级 | 典型归属 | 可以沉淀 | 禁止沉淀/复用 |
|---|---|---|---|
| 行业本体/模板 | Echo/平台 | 实体、关系、抽象规则、测试方法 | 患者信息、客户真实数据和商业机密 |
| 通用 Skill | Echo/平台 | 脱敏的业务结构与通用能力 | 客户数据访问权和客户特定上下文 |
| Customer Skill | 客户 | 获准使用的客户配置、参数和接口 | 未经授权的跨客户复用 |
| Golden Dataset | 按协议确定 | 脱敏、合成或明确获准的样例 | 未经授权的患者或商业敏感数据 |

向客户解释复用原则时使用清晰边界：带走的是“行业如何理解问题”的抽象方法，不是患者数据、订单、配方、业务参数或客户名单。

## 法规与事实核验

当交付物包含法规名称、条款、审批要求、数据跨境、医疗器械软件分类、GxP、隐私或临床责任结论时：

1. 明确国家/地区、产品/业务类别和时间点；
2. 优先使用监管机构、法律法规数据库、标准组织或企业已批准文件；
3. 记录来源日期与适用范围；
4. 将解释性判断交由 RA/QA/隐私/法务确认；
5. 不把通用 FDE 方法论描述成监管批准或法律意见。
