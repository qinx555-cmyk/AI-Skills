# 医疗 FDE 方法论

## 1. AI Native 视角

“业务工作 + AI”是在既有流程中增加一个 AI 环节；AI Native 则重新设计信息产生、讨论、分析、决策、记录和下一步执行的连接方式。

例如研发实验结束后，实验员、研发工程师、负责人和 AI 可以在同一协作空间复盘。AI 调用获准使用的企业知识库与历史实验资料补充证据，随后生成待审核的实验记录、实验报告、质量记录和下一轮实验计划。各输出仍由对应责任人审核批准。

FDE 的工程任务是把“研发记录很乱”之类诉求继续拆成：

- 数据在哪里、质量如何、谁有权限；
- 实验过程怎样记录，异常怎样处理；
- 哪些内容进入实验报告或质量体系；
- 谁审核、谁批准、谁对结果负责；
- 历史资料怎样检索，下一轮计划怎样形成；
- AI 错误时怎样发现、升级、回滚和停用。

## 2. 实施策略

- 成熟企业通常流程和质量体系较稳定，但组织变更成本高；宜从单一模块切入，跑通后扩展。
- 小型企业基础可能较弱，但决策链短；可在成熟行业基线出现后以配置方式快速采用。
- 质量体系是优先切入点之一：让业务发生时同步形成受控记录，减少“真实流程”和“补录体系”分离。
- 私有化或本地化部署不是默认答案。根据数据敏感度、商业机密、监管要求、性能、成本和可运维性选择；需要的是“懂行业、懂企业且边界清楚”，而非模型知道一切。

## 3. 组织角色

| 角色 | 主要责任 | 典型输出 |
|---|---|---|
| 管理层/项目 Sponsor | 决定优先级、投资节奏、风险边界、项目目标与资源 | 项目授权、预算、成功标准 |
| Echo 团队 | 建设行业本体、模板、Skill、Connector、评测套件与版本治理 | Industry Kit / Baseline |
| Delta / FDE | 进入现场，完成发现、接入、Demo、验证、上线、问题处理与反馈 | 客户可运行系统、Delta 反馈单 |
| 领域专家 | 对医疗、研发、临床、注册、质量等专业内容作判断并把守风险 | 专业结论、风险签字 |
| FDE/PM/项目负责人 | 对齐需求、优先级、里程碑、客户协作和验收 | 计划、KPI、验收记录 |
| 客户业务/IT/合规 | 提供真实流程、获准数据、测试环境，并承担约定的业务责任 | 系统接入、验收与责任确认 |

## 4. 风险分层

| 等级 | 典型场景 | AI 权限 | 最低要求 |
|---|---|---|---|
| R1 低风险 | 文献检索、会议纪要、SOP 问答 | 可自动生成 | 来源可核验、抽样复核、保留日志 |
| R2 中风险 | 实验分析、注册一致性检查、投诉调查、CAPA 辅助 | 建议 + 人审 | 保留依据、指定审核人、异常升级 |
| R3 高风险 | 诊断/治疗决策支持、质量放行、正式注册提交 | 不得自动作最终决定 | 强制专业复核、审计、回滚、批准 Gate |

风险等级由“最坏可合理预见后果”决定，不因模型平均准确率高而自动降低。

## 5. 五维准入

| 维度 | 核心问题 | 建议结论 |
|---|---|---|
| 业务价值 | 是否高频、耗时，且对收入、质量、周期或风险有明确影响 | 高 / 中 / 低 |
| AI 可行性 | 数据是否存在且可用，输出是否可验证，模型能力是否匹配 | 可行 / 条件可行 / 不可行 |
| 风险 | 错误会造成什么后果，是否涉及医疗、质量或合规责任 | R1 / R2 / R3 |
| 复用性 | 是否为同类客户的共性流程，能否把定制转为配置 | A / B / C |
| 数据与合规 | 权属、授权、脱敏、部署、日志和保留策略是否满足要求 | 通过 / 有条件 / 不通过 |

No-Go 信号：没有业务责任人或验收人；没有合法可用数据或安全测试环境；输出不可验证却计划自动执行高风险决策；只有人天定制且无复用空间；需求持续漂移，不能形成首个可测量闭环。

## 6. 现场发现

访谈必须覆盖管理层、业务负责人、一线人员、IT/数据、RA/QA/隐私/法务。Shadowing 应形成：

- 业务流程地图：正常路径、异常路径、人工交接点和责任角色；
- AI 机会清单：价值、风险、数据条件和复用性；
- 数据资产清单：来源系统、字段、质量、权限、保留期限和数据等级；
- 已知约束清单：法规、质量、系统、网络、组织和责任边界。

不要把访谈陈述直接当成事实；用现场观察、系统记录、样例文件和不同角色交叉验证。

## 7. 复用成熟度

| 阶段 | 交付形态 | Delta 工作 | 资产状态 |
|---|---|---|---|
| 首客 | 探索 + 定制 | 开发为主 | V1.0，接口和假设较多 |
| 2–4 客户 | 行业本体/Skill 默认化 | 适配 + 数据接入 | 核心路径稳定，扩展点增加 |
| 5–8 客户 | 配置 + 少量定制 | 配置为主 | Industry Kit 成形 |
| 更多客户 | 客户/伙伴自助 | 复杂场景才进入 FDE | 版本小步迭代，复用率上升 |

若第十个同类客户仍需从零开发，模式仍是项目制，而非产品化 FDE。
