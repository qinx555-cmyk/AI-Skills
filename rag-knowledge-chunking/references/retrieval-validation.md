# 检索验收与故障定位

先明确每道题的真实答案、必需证据（版本+块/页/表行）和期望行为。知识不足的题以明确说明不足为正确结果；不能由系统回答反过来生成唯一标准答案。

问题集覆盖：

| 类型 | 示例 | 检查点 |
|---|---|---|
| 事实 | 某型号内存是多少？ | 数值、单位与型号 |
| 同名子标题 | A/B 型号各自技术参数 | 上级标题上下文不混淆 |
| 表格关系 | 哪些型号支持协议 X？ | 必须覆盖需要比较的各行/列，不把 Top K 片段当完整集合 |
| 数值条件 | 哪些型号能在 -25°C 工作？ | 最低温度 ≤ -25°C 且最高温度 ≥ -25°C；负号与端点正确 |
| 版本 | 当前有效 SOP 和历史执行 SOP 有何不同？ | 版本及执行证据；不以相似分数代替版本条件 |
| 无答案 | 原文未给出的参数 | 不生成数值 |
| 权限 | 用户无权访问的资料 | 候选、引用及原件均不交付 |

每题记录：query、expected_sources、candidate_sources、reranked_sources、final_context_sources、answer、failure_stage。保存配置、索引版本和数据版本以便比较。

排查顺序：

1. 原件本来有答案吗？解析后的 Markdown 有没有？缺失先修解析。
2. 答案是否被切散，标题、表头、单位是否还在？修切割与上下文。
3. 正确片段是否进入初始候选？检查关键词、语义匹配、过滤范围和候选数量。
4. 候选中存在却未进最终上下文：分别检查库级、汇总节点级 Rerank、Top K、分数阈值、元数据过滤和总上下文预算。调一个因素后复测，不能只提高 Top K 到无限。
5. 上下文正确但答案错：检查提示词、数值比较、跨行聚合和引用；避免将生成错误误诊为切片错误。

指标至少记录必需证据覆盖率、错对象/错版本数、无答案题行为及来源可回读情况。小样本结构检查只能说明机制有效；真实业务质量需真实问题集。完整集合/统计走结构化查询或足够完整的表格证据，不能把有限 Top K 当作全量。

不固定跨模型通用阈值，不假定不同重排器的分数同标度。Embedding、混合检索、重排未配置时，明确记录未执行的阶段，不以关键词结果冒充。
